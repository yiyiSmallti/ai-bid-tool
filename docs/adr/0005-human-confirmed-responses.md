# 0005 模型提议与人工确认分离的响应卡片

状态：已采纳。

## 背景

抽取要求、材料声明、模型响应和人工决定具有不同的可信度与生命周期。直接将模型文字写入
偏离表，会把缺材料、未审阅或失效的内容当成已完成响应；把所有程序条款强制写成响应，
又会制造大量没有业务意义的承诺。重新抽取、修改资源或替换材料也不能改写既有确认。

## 决定与理由

- 卡片固定到一个任务中明确选择的成功抽取作业及其要求，不隐式选择最新作业，也不跨作业
  合并。修订只追加，当前指针采用预期版本检查，使人工审阅的对象可追溯。
- 响应种类与条款处置分开。`evidence` 需要真实材料，`commitment` 表达可兑现的义务且没有
  Evidence；`respond` 与 `comply_only` 由人按职责决定。模型只写建议，避免建议自行消除缺口。
- 采用专业单人逐卡确认：技术负责人处理技术职责，投标专员处理商务职责；管理员只为待定
  类别指定职责，不默认获得跨专业确认权。令牌、内外部 agent 和 worker 均不能确认、驳回、
  决定补材料、重开、分类或处置。批量处置整批原子提交，减少半批人工决定带来的恢复歧义。
- 声明不升级为证明。元数据、URL、功能实现状态与用户提供的证书页都保留来源性质；页面
  文本匹配不能替代人工看原页，人工确认也不代表系统认证原件真伪。材料义务提示由人记录
  处理决定，不能靠承诺伪称已有证书、报告、截图或附件。
- 模型只生成未确认草稿，不能覆盖待审、已确认和仅遵守卡片。先固定输入，再在实际调用和
  写入时复核；已记录负偏离不得由模型改成无偏离或正偏离。有效的部分候选保留，未完成项
  明确报告，避免付费调用后丢失所有可审阅进展。
- 外发输入采用任务选择白名单，默认遮挡报价/金额、联系人与电话、身份证号、银行账号。
  只有单位人类管理员可关闭遮挡并留下审计，不能由每次模型命令临时覆盖。证书首期只发送
  本地可提取的已选页文本，无文本页明确报告；不隐式增加 OCR 或图像外传。
- 引用必须同时在实际发送文本与固定原文中定位为连续原文，局部 ref 由服务器映射到真实
  材料。遮挡值不反向补回，错误引用不推断修复。无有效引用的材料响应仍是待补材料草稿，
  不自动改为承诺。这样保留失败信息，防止模型选择更容易通过的响应种类来规避材料关口。
- 模型起草复用平台默认模型、官方推理档位和预付费调用准入。缓存固定模型目录、输入与
  规则版本，费用立即按调用入账；取消或拒绝输出不能抹去已发生费用。单位自带模型继续由
  [模型配置契约](../plan/provider-config.md)定义，不作为此流程的前置条件。
- 初稿只组表并逐字复制有效人工确认，不再次调用模型改写。每个要求恰好进入一条主表行、
  一条须遵守记录或一条缺口；实质性条款优先，其余按审核职责分到商务或技术表。负偏离
  不可隐藏，旧初稿保留快照并在读取时重算失效情况，不能直接充当导出授权。

## 权衡与范围

自动遮挡是有版本的文本规则，存在漏检与过度遮挡边界；开启开关不能代替来源选择和人工
审阅。模型读过的材料即使未被引用，也可能影响响应，所以输入材料保守地成为依赖。
这种选择可能增加重新审阅次数，却避免未引用材料变化被忽略。

不包含网页/白皮书取证、材料伪造、Rust 标注、原型图、全文语义校验、评分、模板导出、
要求补录、多抽取作业合并、看板或自动记忆。覆盖完整性只针对指定抽取作业保存的要求，
不声称招标文件没有漏抽。

规则与状态机维护在[响应卡片机制](../notes/response-cards.md)，外发和引用边界维护在
[模型起草与遮挡机制](../notes/model-drafting-redaction.md)，执行步骤见
[CLI 指南](../guides/cli.md#review-responses-and-assemble-a-draft)。
