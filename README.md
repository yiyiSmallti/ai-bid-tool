# AI 标书工具

帮助投标单位读懂招标文件、查证技术参数、校验标书并预估得分。每条结论都能追溯到招标原文或真实证据，人和 agent 通过同一套 API 与 CLI 协作。

> 当前处于设计阶段。本仓库已归档 v0.2 设计草稿，尚未实现业务功能。

## 设计文档

完整范围、架构、数据模型、CLI 约定和分期计划见 [AI 标书工具设计文档](docs/AI%20标书工具设计文档.md)。文档中的分期日期为草稿计划，待开发启动时确认。

## 核心能力规划

- 解析 PDF / Word，抽取资格要求、技术参数、评分项和 ★ 号条款，并保留原文页码。
- 按精确产品型号采集官网或白皮书证据，保存来源、截图、时间和哈希。
- 对照软件功能清单生成响应；未实现功能的界面强制标注“设计原型”。
- 人工确认证据后生成响应表，校验废标和扣分风险，逐项预估得分，按单位模板导出 Word。
- 提供任务看板、单位资源库、服务配置和分层记忆，支持外部 agent 调用 CLI。

## 架构与技术方向

网页、CLI 和 agent 共用 API；耗时工作通过后台作业执行。

| 部分 | 设计选型 |
| --- | --- |
| API / CLI / 数据校验 | FastAPI / Typer / Pydantic |
| 数据与记忆 | PostgreSQL + pgvector，使用行级安全策略隔离单位 |
| 文件存储 | S3 兼容对象存储 |
| 文件处理 | PyMuPDF / python-docx |
| 浏览器取证 | Playwright |
| 证据标注 | Rust：clap、serde、image、sha2 |
| 前端 | Vue 3 + Vite |
| 部署 | Docker Compose |

后台队列、默认模型、OCR 和搜索服务尚待选定。

## 核心约束

- 证据来自真实页面或文件，无法查证时明确记录，不能生成厂家证明材料。
- 未经人工确认的证据不能进入响应表和导出文件。
- 内置和外部 agent 不能确认证据、修改已确认卡片或导出。
- 单位的业务数据、文件、资源、模型配置和记忆必须隔离。
- 记忆影响处理方式，不能替代参数证据。
- 任务锁定资源版本，变更应显式操作并可追溯。

## 开发顺序

1. 服务端、多租户隔离与存储基础；CLI；解析、要求抽取和校验。
2. 产品及功能资源库；取证、证据标注、软件响应和响应表。
3. 看板、评分和导出；角色与令牌；服务配置及项目、单位记忆。
4. 用户与全局记忆；审计、用量配额、MCP 和私有化部署。
